# 관리자 웹 운영

<a id="web"></a>

관리자 화면은 컨트롤러의 `/`에서 열며 정적 파일은 `/ui/`로 제공합니다. React/Vite 빌드 결과를 컨트롤러 바이너리에 포함하므로 운영 서버에서 Node.js나 외부 CDN이 필요하지 않습니다. 화면 파일에 토큰·서명 개인키를 넣지 않습니다.

<a id="authentication"></a>

## 접속과 인증

설정한 TLS 주소와 CA를 사용합니다. 화면에서 관리자 토큰을 입력하면 같은 origin의 API에 Bearer 헤더를 붙입니다. 토큰은 탭의 `sessionStorage`를 사용하며 쿠키를 보내지 않습니다. 공용 브라우저에서 로그아웃하고 토큰을 개발 로그·스크린샷·URL에 남기지 않습니다. TLS 검증을 끄거나 토큰을 번들에 하드코딩하지 않습니다.

API가 401을 반환하면 토큰과 컨트롤러의 `admin_tokens`를 확인합니다. 컨트롤러의 관리자 이름은 감사 로그의 조작자 이름에 사용됩니다. 화면의 정적 자산이 열린다는 사실만으로 관리자 API 인증이 완료된 것은 아닙니다.

<a id="pages"></a>

## 화면에서 확인할 증거

| 화면 | 확인·조작 |
| --- | --- |
| 개요 | 링 목표, 자동 보류, 빌더·호스트 전체 상태 |
| 작업 | 포함 패치, 빌드 로그, VM 모드·키·단계 결과와 SHA, 일반·출시 전 승인 |
| 호스트 | 실제 활성·전환, 보안 신호, 인증서 등록·MOK pending, 배포 제외 사유, 준비 대상과 재부팅 결과 |
| 패치 | 활성/비활성, diff, 미해결·관리자 제외 증거; 상태 변경 후 새 빌드 필요 |
| CVE 현황 | 전체 공급사 목록과 기준 패키지·실제 포함 증거, 미확인·미해결 항목 |
| 설정 | 현재값과 파일값, 공개 서명 키·만료·등록 수·경고 |
| 감사 | 승인·승급·롤백·설정 변경·MOK 비밀번호 조회 등의 기록 |

서명 설정 화면은 공개 메타데이터를 표시합니다. 개인키 경로·서명 명령을 API에서 편집하는 화면이 아닙니다. 키 교체와 MOK 비밀번호 조회 명령은 [서명 운영](secure-boot.md#secure-boot)을 사용합니다. 출시 전 표시는 일반 양수 버전과 구별하며, 명시 승인·승급과 VM 시험 요구를 그대로 적용합니다.

운영 설정 변경은 `data_dir/settings.json`에 저장됩니다. 재시작만으로 파일 설정으로 돌아가지 않으므로 복구 시 두 파일을 함께 검토합니다. 화면에서 자동 진행을 껐어도 기존 링 목표는 유지되고 인증서 위험 감사도 계속됩니다.

<a id="development"></a>

## 화면 변경 확인

프런트 변경은 저장소의 Node 버전 조건을 만족하는 개발 환경에서 시험·빌드합니다. 실제 배포 바이너리를 만들 때 내장 번들도 포함해야 합니다.

```sh
make web
make test-web
make build
```

`make test-web`는 화면 단위 시험과 소스·내장 번들 일치 검사를 실행합니다. `make test-web-browser`와 `make test-web-demo`는 별도의 브라우저 시험입니다. 가짜 데이터 모드는 `make dev-web` 또는 `npm run dev --prefix web`이며 실제 컨트롤러로 요청하지 않습니다. 정상·혼재·빈 상태의 서명·출시 전·제외 시나리오를 확인할 수 있지만 실제 커널 시험 증거로 사용하지 않습니다.

실제 API 개발은 `KPCTL_DEV_URL`을 설정하고 `npm run dev:api --prefix web`를 사용합니다. HTTPS 프록시의 CA 신뢰를 준비하며 검증은 켜져 있습니다. mock 모드와 실제 API 주소를 함께 설정하면 시작을 거부합니다.
