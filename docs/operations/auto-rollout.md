# 자동 승인과 링 승급

<a id="auto-rollout"></a>

`auto_rollout.enabled`의 기본값은 `false`입니다. 켜면 컨트롤러가 일반 관리자 승인·승급과 같은 함수를 사용합니다. 기본 확인 주기는 60초이고 자동 승급 관찰 시간은 1440분입니다. `approve_only=true`면 첫 링 승인까지만 자동이며 다음 링은 관리자가 승급합니다.

웹에서 바꾼 운영 설정은 `data_dir/settings.json`에 저장되어 다음 시작에도 `controller.json`의 초기값보다 우선합니다. 웹 설정의 현재값과 파일값을 함께 확인합니다. `kpctl auto pause`는 전역 일시 중지이며 설정의 enabled와 별도로 보존됩니다.

<a id="gates"></a>

| 단계 | 진행 조건 |
| --- | --- |
| 첫 링 승인 | 새 Ubuntu 수집 패치가 있는 `built` 작업, 첫 링의 검증 가능한 호스트 상태, 서명 성공, 설정된 VM 시험 통과 |
| 다음 링 승급 | 이전 링 목표 적용, 최근 보고, 오류 없음, 실제 활성 모듈, 전환 완료, 링별·자동 관찰 시간 충족 |
| 관리자 승인 필요 | 수동 제출 패치 포함, 새 패치 없는 재빌드, 출시 전 작업 |
| 자동 진행 보류 | 커널별 hold, 수집·시험 검토 문제, 적용 대상 호스트 오류, 서명 또는 VM 시험 실패 |

서명 자격에서 제외된 호스트는 이전 링 건강 검사에서 제외하며 이유를 상태와 승인·승급 응답에 표시합니다. 제외 때문에 기존 모듈을 내리지 않습니다. 이전 링에 호스트가 전혀 없으면 검증 불가로 멈추지만, 호스트가 모두 명시적으로 제외된 경우에는 제외 목록을 남기고 진행할 수 있습니다. 카나리 대상을 실제로 보호하고 있는지는 운영자가 따로 확인해야 합니다.

자동 진행은 롤백을 실행하지 않습니다. 롤백 후에는 같은 패치가 다시 누적될 수 있으므로 해당 커널이 자동 보류됩니다. 패치 상태와 원인을 검토한 뒤 빌드·승인하고 보류를 해제합니다. 수집 실패를 관리자 제외로 처리해도 CVE가 해결된 것으로 표시하지 않습니다.

<a id="control"></a>

```sh
sudo kpctl auto
sudo kpctl auto hold 6.8.0-85-generic
sudo kpctl auto clear 6.8.0-85-generic
sudo kpctl auto pause
sudo kpctl auto resume
```

clear/resume는 원인 확인 후 실행합니다. 보류 해제가 VM 시험, 서명, 전환 완료 검사까지 없애지는 않습니다. 자동 배포를 꺼도 컨트롤러는 인증서 만료·삭제 키 위험을 주기적으로 감사하며 동일 경고를 반복 기록하지 않습니다.

<a id="prerelease"></a>

출시 전 누적본은 별도 링 overlay에 놓입니다. 정식 링 버전은 보존되며 overlay가 있으면 해당 링은 음수 버전을 목표로 삼습니다. 출시 전 배포 중인 트랙은 자동 승인·승급을 멈춥니다. 관리자는 `--prerelease`로 승인·승급하고, 정식 버전으로 복귀할 때 일반 승인·승급·롤백이 해당 overlay를 해제하는지 상태에서 확인합니다. 이전 정식 패치가 빠진 오래된 출시 전 작업은 승인되지 않으므로 최신 정식 누적 범위로 다시 빌드합니다.
