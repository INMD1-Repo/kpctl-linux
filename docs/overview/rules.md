# 배포를 판단하는 규칙

[목차](../README.md) · [구조](architecture.md)

## 여섯 가지 기본 조건

| 조건 | 구현에서 확인하는 내용 |
|---|---|
| 보호 범위가 누적돼야 함 | 커널의 활성 패치 전체로 작업을 만들고 atomic replace 모듈 하나로 적용합니다. 개별 `.ko`를 임의로 올리는 경로는 이 누적 상태에 반영되지 않습니다. |
| 번호를 부여하는 곳이 하나여야 함 | 정식 버전과 출시 전 전용 카운터 모두 컨트롤러가 관리합니다. 같은 채널의 새 누적 작업은 이전 미배포 작업을 폐기합니다. |
| 다음 링에 앞선 증거가 있어야 함 | 일반 승급은 이전 링의 목표·실제 활성 모듈·전환·보고 신선도·관찰 시간을 검사합니다. 배포 자격에서 제외한 호스트는 이 승급을 막지 않습니다. |
| 다른 공급자의 보호를 덮지 않아야 함 | 외부 라이브패치가 활성 또는 전환 중이면 에이전트가 다운로드 전과 적용 직전에 거부합니다. 직접 정리하는 모듈은 설정한 자기 접두사 범위입니다. |
| 재부팅 권한이 정확한 대상에 묶여야 함 | 현재 boot ID와 검증한 다음 커널에 연결한 5분짜리 1회 승인을 사용합니다. claim과 실행 직전에도 VM·파일·잠금·승인 상태를 확인합니다. |
| 빌드 입력이 대상과 맞아야 함 | LTS 시리즈와 대상 GCC를 맞추고 공식 커널 config·인증서·vermagic·심볼 CRC 검사를 유지합니다. sandbox 오류 때문에 호스트 환경으로 전환하지 않습니다. |

관리자의 강제 승급은 건강·관찰 검사를 건너뛰는 별도 조작입니다. 호스트 즉시 업데이트도 링보다 앞선 **정식 승인본**을 선택할 수 있습니다. 두 조작은 승인 전 검토와 카나리 판단을 대체하는 자동 안전 검증이 아닙니다. 출시 전 누적본은 명시 플래그가 있는 수동 승인·승급과 VM 시험을 요구하며 즉시 업데이트로 적용하지 않습니다.

## 수집이 멈추는 경우

정식 APT 버전이나 대응 Git 태그를 확인하지 못하면 자동 경로가 개발 태그를 대신 쓰지 않습니다. compiler·인증서·의존성·분류하지 못한 실패는 검토 대상으로 남기고 패치를 자동으로 버리지 않습니다. 누적 빌드 실패 뒤에도 입력을 보존합니다.

수집·빌드·호스트 오류로 걸린 자동 배포 보류는 나중 성공만으로 해제하지 않습니다. 운영자가 원인과 후속 누적본을 검토한 뒤 `kpctl auto clear`로 해제합니다. 출시 전 수집의 별도 시험 실패 기록도 정식 실패 기록을 지우지 않습니다.

## 보안 상태와 재부팅

Secure Boot, lockdown 또는 sig_enforce 중 읽지 못한 값이 있으면 서명 필요로 판단합니다. 키 등록 상태가 명확히 미등록이면 해당 호스트를 제외하고, 예전 에이전트처럼 판정을 모르면 active 사본과 경고를 제공합니다. 제외는 기존 보호를 유지하도록 처리하며 v0 롤백과 구분합니다.

MOK 등록 예약 자체는 재부팅하지 않습니다. 자동 커널 점프는 `auto_prepare_kernel` 조건과 `auto_jump_kernel_hosts`의 정확한 호스트 ID 허용 목록을 모두 통과해야 합니다. 그 외에는 준비된 새 GA 커널에 대한 관리자 승인이 필요합니다. 등록 예약, 디스크 커널 준비, 재부팅 승인을 각각 확인해야 합니다.
