# 지원과 검증의 한계

[목차](../README.md)

## 커널과 보호 범위

- 기본 대상은 [지원 식별표](../../internal/model/lts.go)의 GA generic 계열입니다. HWE의 Ubuntu signature는 차단하지만 signature를 보내지 않는 예전 에이전트는 이름이 같은 HWE를 구별할 수 없습니다. 혼재 환경은 에이전트를 먼저 갱신하세요.
- 수집은 선택 경로와 CVE 정보를 통과한 수정에 한정됩니다. CNA 대조를 켜도 upstream ID를 찾지 못한 수정이나 필터 밖 경로까지 수집하지 않습니다. OSV 대조 결과는 전체 보호율이나 공격 차단 시험 결과가 아닙니다.
- 라이브패치가 디스크 커널과 `uname -r`을 바꾸지는 않습니다. 지원하지 않는 수정, 필요한 ABI 변화와 실제 커널 교체는 준비·드레인·승인 재부팅으로 다룹니다.
- native klp-build 선택은 커널 번호 추측이 아니라 대상 config의 `CONFIG_KLP_BUILD=y`를 확인합니다. 빌드 도구가 처리할 수 없는 변화는 별도 검토가 필요합니다.

## 실행과 복구

- 개별 시험·누적 빌드·VM 검사를 통과해도 모든 실제 호스트와 업무 경로의 안정성이 증명되는 것은 아닙니다. 배포 대상과 동일한 커널·펌웨어 조건에서 별도로 검증합니다.
- 에이전트는 알려진 외부 활성·전환 패치를 검사하지만 다른 공급자 데몬과의 전역 잠금을 제공하지 않습니다. 다른 라이브패치 공급자와의 동시 운영을 전제로 사용하면 안 됩니다.
- 새 부팅용 설치본과 이전 설치본 정리는 여러 파일의 작업입니다. 중간 종료 후 에이전트가 복구하기 전에 재부팅하면 여러 설치본이 남아 있을 수 있습니다. 부팅 시 kpatch 서비스의 로드는 에이전트의 다운로드 ELF 검사 경로와 다릅니다.
- 서명 자격에서 제외된 호스트는 기존 모듈을 유지합니다. 구 에이전트의 등록 상태 미확인은 경고와 active 사본을 사용하므로 실제 신뢰 등록이 없으면 호스트 로드에서 실패할 수 있습니다.
- 이미 허용된 같은 버전의 서명 바이트는 유지하고 새 버전부터 active 키를 적용합니다. 원본·해시 pin이 없는 과거 배포본으로 새 키의 이전 누적 사본을 만드는 절차는 거부합니다.

## 재부팅과 운영 기반

- 5분 승인은 에이전트가 재확인하는 권한입니다. GRUB 자체의 시간 만료 기능이 아니며 에이전트가 멈춘 동안 미실행 선택을 즉시 정리한다고 보장하지 않습니다.
- 기본 커널 준비는 확인 가능한 GA generic·GRUB·지원 부트 파일 구성에 한정됩니다. 로컬 VM 프로세스 검사만으로 모든 스케줄러·가상화 제품의 업무 상태를 알 수는 없습니다.
- 허용 목록의 자동 점프도 조건이 맞은 지정 호스트의 1회 승인입니다. root의 별도 재부팅·전원 장애·패닉을 제어하지 않습니다. MOK 콘솔 승인은 별도 운영 접근이 필요합니다.
- 컨트롤러는 JSON 파일을 저장하는 단일 프로세스입니다. 같은 data directory에 여러 컨트롤러를 실행하는 클러스터 저장소, DB 트랜잭션과 빌더별 독립 인증을 제공하지 않습니다.
- `max_kernels`, 디스크 정리와 입력 캐시는 저장 공간을 관리하는 기능입니다. 공간 부족을 무시하거나 공식 config·인증서·GCC·CRC 조건을 낮추는 기능이 아닙니다.

출시 전 누적본의 승인·승급·롤백은 명시 조작을 요구하며 활성 overlay가 있으면 해당 커널의 자동 배포를 보류합니다. 출시 전 후보를 정식 배포 수정과 동일하게 검증했다고 보고하면 안 됩니다.
